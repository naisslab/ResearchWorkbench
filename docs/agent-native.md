# Agent native 工作台

目标：用户在界面上能做的研究操作，Agent 也能通过结构化工具完成；用户在界面上能看到的项目状态，Agent 也能按需读取。Agent 仍然只在用户发起的请求中运行，所有写入都可审阅、可撤销。

## 现状与问题

Agent 通过 Codex 的 shell 和文件编辑工作，应用内只有一个工具 `record_writing_items`。编译、投稿检查、文献查询、PDF 批注、统一搜索、项目阶段和里程碑都只能在界面上操作。新增工具时还有三处结构问题：

1. 工具在 Codex 线程创建时固定。旧对话保留原生历史，不注册新工具；这一点保持不变，但需要记录每个线程实际拥有的工具，而不是一个只针对写作工具的布尔值。
2. 工作区由界面整体保存。主进程若直接修改工作区，会被界面随后的整体保存覆盖。因此写工作区的工具继续由界面执行，主进程只负责转发和等待回执。
3. 工具分发写死在一个工具名上，只读模式检查也写在处理函数里。

## 工具注册表

主进程维护一份工具注册表。每个工具声明名称、说明、输入 schema、一句开发者指令，以及两个安全属性：

- **写入**：修改工作区、批注或构建产物。Read only 权限下拒绝执行。
- **含外部文本**：返回 PDF 正文、批注引文等第三方文档内容。Full access 权限下拒绝执行；对话一旦读到这类内容，之后的请求即使选择 Full access 也按 Default permissions 运行，与附加 PDF 摘录的规则一致。

每个工具在主进程执行，或通过界面桥执行。新线程注册全部工具，并把工具名列表保存在对话里；恢复线程时只提供该列表中的工具和对应指令。旧对话的 `writingTools: true` 视为只拥有 `record_writing_items`。

## 界面桥

主进程向界面发送 `{ id, projectId, tool, input }`，界面执行后回复 `{ ok, result }` 或错误。超时、停止或窗口关闭都会让工具调用失败，Agent 不会误报成功。界面桥承担两类工作：

- 工作区写入：通过现有的保存流程提交，并显示带 Undo 的提示条。
- 稿件检查：读取最新的稿件文件、参考文献和编译 PDF，调用与 Build log 相同的检查函数。这样不依赖界面当前缓存的状态，Agent 修改文件后立即检查也能得到新结果。

## 工具

| 工具 | 执行位置 | 写入 | 含外部文本 | 作用 |
|---|---|---|---|---|
| `record_writing_items` | 界面 | 是 | 否 | 追加待办和研究笔记（已有） |
| `update_project` | 界面 | 是 | 否 | 完成、重开、阻塞或解除阻塞待办；修改项目阶段；添加里程碑 |
| `get_project` | 主进程 | 否 | 否 | 项目阶段、目标会议、研究问题、页数限制、匿名评审、里程碑和关联日期 |
| `compile_manuscript` | 主进程 | 是 | 否 | 用工作台的编译流程编译稿件，返回结构化问题和页数，并更新 PDF 预览与 Build log |
| `check_submission` | 界面 | 否 | 否 | 运行投稿检查和参考文献检查，返回与 Build log 相同的结果 |
| `lookup_reference` | 主进程 | 否 | 否 | 用 DOI、arXiv 或标题查询 doi.org、arXiv 和 Crossref，返回 BibTeX 或候选文献 |
| `search_workspace` | 主进程 | 否 | 是 | 在当前项目中搜索文件、PDF 正文、批注和历史对话 |
| `list_feedback` | 主进程 | 否 | 是 | 列出当前项目的 PDF 批注及状态；当前编译 PDF 上的批注附带 SyncTeX 源码位置 |
| `reply_to_feedback` | 主进程 | 是 | 否 | 在批注上记录 Agent 的处理说明，状态显示为待用户确认 |

说明：

- 项目阶段、会议等信息曾因可能过期而移出每轮上下文。`get_project` 让 Agent 在需要时主动读取，不再每轮注入。
- `compile_manuscript` 在 Agent 沙箱外运行，因此不弹出 latexmkrc 信任对话框：已信任的配置照常使用，未信任的配置被跳过，结果中注明。编译使用与用户相同的构建槽，用户编译时 Agent 不能同时编译。
- `lookup_reference` 只访问三个固定的文献服务，查询文字最长 300 字符。文献元数据视为参考数据，不标记为含外部文本。
- `reply_to_feedback` 不修改批注本身。处理说明单独保存，界面的整体保存不会覆盖它。只有用户能把批注标为 Resolved。
- SyncTeX 不单独做成工具：Agent 需要它的场景是把 PDF 批注定位到源码，已由 `list_feedback` 提供。

## 界面

- Work log 为每次工具调用记录一行，例如 "Compiled manuscript: 2 problems"。
- Agent 编译完成后，工作台更新 Build log、问题列表、PDF 预览和投稿检查。
- PDF 批注列表显示 "Open · Agent replied" 和 Agent 的说明。
- Build log 有问题或检查失败时显示 **Ask Agent to fix**，把修复请求填入 Agent 输入框，由用户发送。

## 验证

- 单元测试：注册表的权限与外部文本规则、线程工具列表与旧对话迁移、界面桥的回执与超时、日志解析共享模块、批注回复在界面保存后保留。
- 原生 Codex 运行时用本地模型响应 fixture 验证新工具的动态调用。
- 界面冒烟测试：Ask Agent to fix 预填请求，Agent 回复在批注列表显示。
